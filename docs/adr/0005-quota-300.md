# ADR 0005 — Raise the daily request ceiling from 200 to 300

- Status: accepted
- Date: 2026-10-21
- Supersedes: none
- Decision owner: project owner

## Context

The kernel's initial daily ceiling was 200 network actions. Live testing on
2026-10-21 used 184 actions without a risk signal, rate limiting, 403/429, or
captcha. The owner asked to raise the ceiling to 300 for day-to-day research.

`AGENTS.md` states that hard limits may only be tightened, and that loosening
requires a new ADR. This is that ADR.

## Decision

Change `HardLimits.daily_request_limit` from 200 to 300.

No other limit changes:

- minimum interval stays 3000 ms (plus random jitter, never below the floor);
- concurrency stays 1;
- one page per call, `page` 1–3, `limit` 1–50;
- a plan stays within 40 actions and 120 s;
- a risk signal still stops the plan and writes the 24-hour cooldown.

## Consequences

- The absolute worst case rises by 50% (200 → 300 network actions/day), but the
  cadence is unchanged: at least 3 s between actions, so 300 actions still span
  at least 15 minutes of wall-clock time.
- Quota remains a ceiling, not a target; callers should not try to exhaust it.
- Captcha handling is unchanged: stop, notify the user, and let the user solve it
  in the browser. After manual verification the user may explicitly run
  `scholar-search reset --confirm`; there is no automatic retry.

## Alternatives considered

- Keep 200: rejected because the owner needs more daily capacity and 200 was
  stable in live testing.
- Remove the daily ceiling: rejected; a hard ceiling plus the 3 s floor is the
  main protection against accidental high-frequency access.
